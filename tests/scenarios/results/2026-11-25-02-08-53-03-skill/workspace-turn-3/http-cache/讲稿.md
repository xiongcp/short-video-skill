# 为什么 HTTP 缓存能让网页变快？

- 受众：不懂网络的普通人
- 目标时长：90 秒（估算约 91 秒，346 字）
- 看完能说清：相同的内容第二次不用跨大半个地球重新下载，直接从手机本地调取旧副本，网页自然瞬间打开
- 采用的默认值：比例 16:9，浅色主题
- 来源：无外部资料（广为公认的网络基础机制）
- 待核实：口播第二段将服务器与缓存比作千里之外的总仓库与家门口的快递驿站，为通俗化比喻，请核实是否符合预期；口播中提到服务器返回代号三零四（HTTP 304 Not Modified）表示内容未变继续用旧的，请核实通俗解释是否准确易懂
- 确认状态：待确认（revision 2）

## s01 为什么二次打开变快了（约 20 秒）

你常会发现，经常访问的网页刷新时瞬间就打开了。
明明是同一个网页，为什么第二次能快这么多？
秘诀就在浏览器的 HTTP 缓存机制。
HTTP 是网络传输规则，缓存就是本地小仓库。

## s02 本地取货 vs 远道而来（约 28 秒）

第一次访问时，手机要向千里之外的总仓库订货。
配图顺着长途物流慢慢运送，等待时间自然漫长。
但在下载时，服务器会交代把包裹暂存进快递驿站。
看右侧图解，再次打开时，浏览器直接在门口的驿站取件。
省去了远距离长途传输，网页自然瞬间就能呈现在眼前。

## s03 网页内容变了怎么办（约 22 秒）

那如果网站更换了新图片，会不会展示旧内容呢？
并不会，保鲜期一过，浏览器就会询问是否有更新。
如果内容没变，服务器只回一句代号三零四，不用重新传输。
内容更新了，服务器才会传送最新版本来替换。

## s04 随身备忘录的威力（约 21 秒）

这就是 HTTP 缓存让网页飞速加载的秘密。
它把耗时的远距离搬运，变成了本地快速读取。
不仅帮你省下流量，更让平时的浏览丝滑顺畅。
下次秒开网页时，别忘了这个默默工作的本地小仓库。
