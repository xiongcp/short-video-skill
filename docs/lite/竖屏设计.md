# 原生竖屏设计（B）

- 日期：2026-11-26
- 状态：设计待 owner 审阅；审阅通过后写实施计划
- 关系：展开 [个性化路线图](个性化路线图.md) §6.6 的"原生 9:16"，原估 2–3 天，本文按实际改动重估为 3.5–5 天。几何、模板、同台和场景沿用 [画面与同台互动设计](画面与同台互动设计.md)，画质沿用 [超越路线图](超越路线图.md) §5.2，冲突处以本文为准

## 1. 目标

同一份 `project.json` 能出原生 1080×1920 竖屏成片，直接上传抖音、TikTok 和 YouTube Shorts：文字不被平台界面挡住，小青和物件照样同台互动，横屏成片逐帧不变。

## 2. 已确认的决定

| # | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 先做哪个画幅 | 竖屏优先（owner 2026-11-26） |
| Q2 | 横竖是否共用分镜 | 共用一份分镜。`settings.ratio` 定默认画幅，`render.mjs --ratio` 临时换另一种（owner 2026-11-26） |
| Q3 | 同台镜头的竖屏构图 | A 同台一体：小青和物件共用一条地面，字幕在地面下方。不做"上半区图解、下半区人物"的分区，因为那样小青碰不到物件；也不把横屏缩小嵌进竖屏（owner 2026-11-26） |
| Q4 | 实现方式 | 一张几何表，各模块按画幅取值；不复制竖屏专用模块（owner 2026-11-26） |
| Q5 | 横屏是否顺带改 | 不改。横屏字幕放大等放到 A 块 |

## 3. 现状

渲染器把所有画面画在 1920×1080 的逻辑画布上，输出时再按分辨率缩放。排版尺寸是写死在各模块里的常量：

| 位置 | 常量 |
| --- | --- |
| `stage.mjs` | `STAGE_SLOTS`（x 240–1680 五档）、`STAGE_BOUNDS`、小青 x 200–1720、`at` 数字乘 1920 |
| `world.mjs` | `GROUND_Y = 930`；场景陈设按 `kx = width / 1920`、`ky = ground / 930` 分别缩放 |
| `templates.mjs` | `DIAGRAM_ZONES`：`host-left` 1200×400，`full` 1680×740；8 个模板都按横向排 |
| `motion.mjs` | `SPOTS`：left 320、center 960、right 1600 |
| `scene.mjs` | 镜头缓推中心 (960, 540)；SVG 画布 1920×1080；字幕 y 1012、44 px |
| `encode.mjs` | `RESOLUTIONS` 只有横屏；封面和 ASS 的 `PlayRes` 固定 1920×1080 |

`settings.ratio: "9:16"` 现在只影响提示词包的构图。现有测试没有锁定整帧输出。

## 4. 竖屏几何

新增 `scripts/lib/frame.mjs`，导出两组几何：`16:9` 那组就是 §3 的现有常量，`9:16` 那组如下表。各模块从镜头计划拿到当前画幅的几何，不再读写死的常量。

### 4.1 安全区

三家平台都没有官方的普通投稿安全区。查到的第三方估算（1080×1920，单位 px）：

| 位置 | 抖音 | TikTok | Shorts |
| --- | --- | --- | --- |
| 顶部 | 约 220 | 108–200 | 120–154 |
| 底部 | 约 480 | 250–370 | 约 300 |
| 右侧 | 约 140 | 120–164 | 96–192 |

Google 为 Shorts 广告公布的数值更大（顶部 288、底部 672、左 48、右 192），只适用于广告位，不采用。

默认取三家的并集：**顶部 250、底部 480、左 64、右 170**。文字安全框是 x 64–910、y 250–1440；标题、物件标签和字幕都必须在框内，背景和场景可以铺满。数值集中在 `frame.mjs` 一张表里，owner 真机预览后可以直接改。

来源：[AdMake AI](https://www.admakeai.com/blog/vertical-video-dimensions-2026)、[Ignite Social Media](https://www.ignitesocialmedia.com/content-creation/what-are-the-safe-zones-for-tiktoks-and-instagram-reels/)、[revid.ai](https://www.revid.ai/tiktok-safe-zone)、[Socialync](https://www.socialync.io/tools/safe-zones/youtube-shorts)、[Google 通用安全区](https://services.google.com/fh/files/misc/universalsafezones-youtube.pdf)、[AdaptlyPost](https://adaptlypost.com/blog/social-media-safe-zones-2026-complete-guide)、[reap.video](https://reap.video/blog/short-form-video-safe-zones)（2026-11-26 检索）。

### 4.2 几何表

| 项 | 16:9（不变） | 9:16 |
| --- | --- | --- |
| 逻辑画布 | 1920×1080 | 1080×1920 |
| 文字安全框 | 整个画面 | x 64–910，y 250–1440 |
| 标题带 | y 48–150 | y 260–370 |
| 空中物件层 | y 160–470 | y 400–720 |
| 中间层默认底边 | y 762 | y 1012 |
| 地面 | y 930 | y 1180 |
| 同台站位 | left 240，mid-left 600，center 960，mid-right 1320，right 1680 | 名字不变：160、325、490、655、820 |
| 小青可走范围 | x 200–1720 | x 140–860 |
| `move` 的 left/center/right | 320、960、1600 | 200、490、780 |
| `host-left` 图解区 | x 640，y 48，1200×400 | x 64，y 260，846×640 |
| `full` 图解区 | x 120，y 120，1680×740 | x 64，y 260，846×940 |
| 小青高度 | 400 px | 400 px |
| 字幕 | 中心 (960, 1012)，44 px，单行 | 中心 x 540，y 约 1250–1420，60 px 粗体加纸色描边，每行不超过 12 字，最多 2 行 |
| 镜头缓推中心 | (960, 540) | (540, 960) |

- 字幕以 540 居中、宽度限 740（左右各让 170），看起来居中，也碰不到右侧的点赞栏。
- 小青保持 400 px，在竖屏里约占画面高度的 21%，比横屏更显眼。
- `at` 写成 0–1 的数字时乘当前画布宽度，不再固定乘 1920。

## 5. 画面元素

分镜数据、cue 的含义和时间轴都不变，同一份数据按竖屏几何重新排版。

### 5.1 图解模板

| 模板 | 竖屏排法 |
| --- | --- |
| `title`、`number` | 不变，按 846 宽自动定字号 |
| `bullets` | 一律单列 |
| `flow` | 从上往下排，箭头朝下；`send` 运送的物件沿竖线走 |
| `compare` | 保持左右两栏，每栏约 400 宽，文字多折行 |
| `bars` | 仍用竖柱，最多 5 根，每根不超过 150 宽 |
| `timeline` | 竖向时间轴，卡片左右交替 |
| `cycle` | 椭圆改成接近正圆 |

镜头之间的同元素补间比较的是前后两帧算出的位置，竖屏照样成立，不用改。

### 5.2 同台

- 站位、边界、小青范围按 §4.2 取值。
- 去掉小青要占的 200 宽，地面一排大约放 3 件中号物件。第 4 件交给现有的自动缩小（最小 0.6 倍）；再多就排不下，出片 QA 报 `STAGE_CROWDED`。
- 横屏规则不收紧。`settings.ratio` 为 9:16 时，`check.mjs` 才给出警告 `PORTRAIT_CROWDED`：一个同台镜头的地面层加中间层超过 3 件，或空中层超过 2 件。

### 5.3 场景背景

- 8 个场景的陈设按陈设分组整理，每组有一个锚点。
- 竖屏下每组整体平移、形状不缩放：锚点在 x < 560 的贴左，x > 1360 的贴右（x − 840），中间的向中心收拢（540 + (x − 960) × 0.5625）；纵向随地面下移 250。
- 竖屏上方多出的墙面留空，或放吊灯、电线这类顶部陈设。
- 8 个场景各出一张竖屏样帧给 owner 看。和小青或物件撞了的陈设，单独给竖屏位置。
- 横屏走原来的缩放，输出不变。

### 5.4 版式切换

小青从 `host-left` 或 `stage` 小跑进出 `full` 时，起止点读几何表；图解区在两个版式之间的缩放过渡换成当前画幅的两个图解区。

## 6. 出片管道

### 6.1 命令与分辨率

```sh
node scripts/render.mjs <项目文件夹> --ratio 9:16
```

- 不写 `--ratio` 时用 `settings.ratio`。`--preview`、`--sample`、`--resolution`、`--fps`、`--master`、`--motion-blur` 都能和它一起用。
- 分辨率按短边算：竖屏 `preview` 540×960、`1080p` 1080×1920、`1440p` 1440×2560、`2160p` 2160×3840；码率、帧率、CRF 和横屏同档一致。

### 6.2 输出位置

| 情况 | 输出到 |
| --- | --- |
| 画幅与 `settings.ratio` 一致 | `out/`，与现在相同 |
| 用 `--ratio` 换成另一种 | `out/9x16/` 或 `out/16x9/`，文件名相同 |

### 6.3 共用与分开

- 共用：配音、`audio/timing.json`、音效和配乐的混音。出第二种画幅不重新合成配音。
- 音效声像改为按 x 占画面宽度的比例算，两种画幅一致；横屏的数值不变。
- 镜头缓存键加入画幅，横竖两版互不干扰。

### 6.4 交付文件

| 文件 | 竖屏版 |
| --- | --- |
| `final.mp4` | 1080×1920 |
| `cover.png` | 1080×1920，仍取第一镜 0.6 秒处的一帧；专门设计的封面属于 C 块 |
| `captions.ass` | `PlayRes` 1080×1920，字号 60，位置对齐竖屏字幕带 |
| `captions.srt`、`chapters.txt` | 两种画幅相同 |
| `contact.png`、`transitions.png` | 按竖屏帧排宫格 |
| `contact-safe.png` | 新增，宫格上画出文字安全框的红线，只在竖屏输出 |

### 6.5 字幕翻页

一句话的字幕先按逗号断（现有逻辑），一段仍超过 2 行×12 字时再按长度断，按说话进度翻页，每页最多 2 行。讲稿的句长规则不用为竖屏改。
