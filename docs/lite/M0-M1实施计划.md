# M0–M1 实施计划：对标评审工具与小青美化

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出对标评审工具（M0），再按 [超越路线图](超越路线图.md) §5.1 精修小青（M1），让 540p 和 H.264 压缩后的画面里，线条不折断、表情看得清、围巾认得出。

**Architecture:** 评审工具是仓库根目录 `tools/` 下的开发脚本，用 `@resvg/resvg-js` 把 SVG 光栅化，用系统 FFmpeg 做压缩往返，图片之间的拼接用 SVG `<image>` 内嵌 PNG 完成，不加依赖。美化只改 `scripts/lib/ink.mjs`、`scripts/lib/rig.mjs` 和 `assets/host/manifest.json`，接口保持向后兼容，最后用 `npm run export-host` 重画所有主持人图片。

**Tech Stack:** Node ≥ 22（ESM、`node --test`）、`@resvg/resvg-js`（开发依赖）、FFmpeg（只有评审工具用）。

**Spec:** [超越路线图](超越路线图.md) §5.1、§7；画法基础见 [火柴人主持人设计](火柴人主持人设计.md) §3–§6。

## Global Constraints

- skill 目录 ≤ 5 MB、≤ 45 个文件；本计划不往 skill 目录加文件。
- skill 不加 npm 运行时依赖；评审工具只用已有的开发依赖。
- 同样的输入画出完全相同的 SVG（种子决定一切随机）。
- 不改 `assets/host/rights.json` 的 `usage`；不改 `profile.json` 的动作、表情、道具名。
- `manifest.json` 已有的键名不改（`ink.width`、`figure.finger`、`poses.*.finger` 等保留原义），只新增键。
- 所有线宽 ≥ 0.0075 H（H = 200 的 540p 主持人上是 1.5 px）。
- 对手的图片只放 `out/ref/`，不提交。
- 每个任务先写失败的测试，再写实现；在分支 `lite/surpass` 上提交；结束前跑 `npm test`。

## Review Focus

1. 深色主题：新的手型、拇指和围巾布条都必须用主题墨色或青色，不能写死浅色主题的颜色（任务 6）。
2. 朝左（`facing: -1`）：拇指和围巾的 V 形缺口要跟着镜像，不能反向（任务 5、6）。
3. 小尺寸：H = 200 时没有低于 1.5 px 的线（任务 3）。
4. 可复现：`smooth`、`taper` 新选项下，同样的输入仍然输出同样的 SVG（任务 2）。
5. 没有 FFmpeg：评审工具跳过压缩往返并打印原因，其他图照常输出（任务 1）。

**Interfaces:**
- Produces:
  - `frameSvg(manifest, { scale = 1 } = {}) -> string`：1920×1080 的 `host-left` 样帧，`width`、`height` 为 1920×scale、1080×scale，`viewBox="0 0 1920 1080"`。内容：纸面 `#fbfaf6`；图解区占位框 x 640–1840、y 80–500，里面一行 64 px 标题"标题示例：缓存"；小青 `idle`、`explaining`，x = 320、ground = 930、种子 `review`；字幕"字幕示例：第二次打开为什么更快"，40 px 黑体，居中于 y = 1010。

### Task 2: 笔触 v2：收细端、圆角、抖动上限

**Files:**
- Modify: `skills/topic-to-video/scripts/lib/ink.mjs`
- Test: `tests/ink.test.mjs`

**Interfaces:**
- Produces:
  - `inkStroke(points, { seed, width, wobble = 0, taper = 'both', smooth = 0 })`，返回值不变。`taper`：`'both'`（现状）、`'start'`（只有起点细）、`'end'`（只有终点细）、`'none'`（全程粗）。单端收细的线宽为 `thin + (thick − thin) × sin(π/2 × s)`，s 是从细端算起的 0–1 位置。`smooth`：采样前先做几次 Chaikin 圆角。
  - `chaikin(points, iterations) -> number[][]`：每次把每段换成 1/4、3/4 两点，首尾两点保持不变。
  - 实际抖动幅度 = `min(wobble, 0.02 × 折线总长)`。

- [ ] **Step 1: 写失败的测试**：
  - `taper: 'end'` 时 `widths[0] === width[1]`、`widths.at(-1) === width[0]`；`'start'` 反过来；`'none'` 时每个值都是 `width[1]`；`'both'` 两端都是 `width[0]`（现有行为）。
  - `chaikin([[0,0],[100,0],[100,100]], 2)` 首点 `[0,0]`、末点 `[100,100]`，相邻两段的转角都 ≤ 45°。
  - 30 px 长的直线、`wobble: 5`：`center` 和 `base` 的最大偏差 ≤ 0.6 px。
  - 带 `smooth: 2, taper: 'end'` 时，同样的输入两次输出的 `d` 完全相同。
- [ ] **Step 2:** `node --test tests/ink.test.mjs`，预期失败。
- [ ] **Step 3:** 实现。
- [ ] **Step 4:** `node --test tests/ink.test.mjs` 通过。此时 `host-rig`、`site` 的哈希测试会因为抖动上限而失败，这是预期的，任务 8 重新导出后恢复；其余测试必须通过。
- [ ] **Step 5: 提交** `feat(ink): one-end tapers, Chaikin corners and a wobble cap of 2% of the line length`
