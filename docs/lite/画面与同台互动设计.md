## 1. 背景与目标

H 阶段的验收片里，小青在 14 个镜头中几乎都站在左下角，图解在右上角，两边隔着半个屏幕。原因在版式本身：`host-left` 把图解锁在 y 48–448 的上方条带，小青站在 y 930 的地面上，他只能隔空指，碰不到任何东西。换一个主题，除了文字和图标，画面也不会变。

目标：

- 小青走进画面中央，和物体站在同一条地面上，开门、搬箱子、坐上去、把东西举起来给观众看。
- 每期先定一个贯穿全片的比喻和画面风格，两个不同主题的联系表一眼看得出不同，又认得出是同一个节目。
- 物体会变：满变空、新鲜变过期、上锁变解锁、被打叉、被盖章；小东西能沿箭头送过去。
- 轻量模型（如 Gemini Flash）写分镜也稳：agent 只写语义（放哪个槽位、什么状态、做什么动作），坐标、比例、手怎么握都由渲染器算。
- 向后兼容：`version` 仍为 1，旧项目不改照常检查和渲染；不加 npm 依赖，不加图片文件。

## 3. 视觉世界（批次 1）

### 3.1 `world` 字段

`project.json` 新增可选的顶层字段 `world`，在写分镜之前定下来，和讲稿、分镜一起在确认①给用户看，不新增确认门。

```json
"world": {
  "metaphor": "缓存是家门口的冰箱，服务器是远处的超市，304 是打电话问超市东西还新鲜吗",
  "style": "paper",
  "scene": "kitchen",
  "custom_props": []
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `metaphor` | 是 | 贯穿全片的一句话比喻，不超过 60 字。分镜里的物件和互动都从它来 |
| `style` | 是 | 风格包，见 §3.2 |
| `scene` | 是 | 全片默认场景，见 §3.3；单个 `stage` 镜头可以用 `shot.scene` 换 |
| `custom_props` | 否 | 本期自定义道具，见 §4.3 |

- 没有 `world` 的项目和现在一样：`settings.theme` 的 `light` 对应 `paper`，`dark` 对应 `night`，不能用 `stage` 版式（`check.mjs` 报 `STAGE_NEEDS_WORLD`）。
- 有 `world` 时，颜色和纸面以 `world.style` 为准，`settings.theme` 仍要写（必填字段不变），只决定 L0 提示词包里\"浅色/深色\"的措辞。
- 服装和配音不放进 `world`：仍写在 `settings.outfit` 和 `voice.preset`。`references/world.md` 按场景推荐服装和配音（例如 `kitchen` 推荐 `apron`，`workshop` 推荐 `hardhat`，`lab` 推荐 `glasses`），agent 定视觉世界时一起提给用户。

### 3.2 风格包

同一种手绘墨线画法，5 套配色和纸面。小青的线条在深色纸面上自动换成浅色（沿用 `manifest.ink.body.dark`），青色围巾和呆毛在所有风格里都不变，这是节目的识别标志。

| `style` | 纸面 | 墨线 | 强调色 | 适合 |
| --- | --- | --- | --- | --- |
| `paper` | 米白手账纸，96 px 浅网格 | 深灰 | 青、黄、红 | 通用讲解（现在的样子，默认） |
| `chalkboard` | 墨绿黑板，几块淡淡的擦痕 | 粉笔白 | 粉笔黄、粉笔红、粉笔青 | 科普、历史、课堂感 |
| `blueprint` | 深蓝底，48 px 细网格加 192 px 粗网格 | 浅蓝白 | 黄、橙、白 | 工程、原理、结构 |
| `kraft` | 暖色牛皮纸，几条长的淡纤维线 | 深棕 | 砖红、墨绿、芥黄 | 生活、商业、怀旧 |
| `night` | 深灰蓝，浅网格 | 浅灰白 | 青、黄、红 | 安全、宇宙、夜间话题（现在的 `dark`） |

- 不用细颗粒纹理，避免 H.264 压出蚊式噪点（沿用 `paperBackgroundSvg` 的做法）。
- 每套风格包给出同一组语义色键：`paper`、`grid`、`ink`、`muted`、`card`、`accent`、`yellow`、`red`、`soft_accent`、`soft_yellow`、`soft_red`。模板、物件、自定义道具只引用色键，不写颜色值。
- 现有 `THEME_PALETTE.light` 和 `.dark` 分别成为 `paper` 和 `night`，颜色值不变，旧项目画面像素不变。

### 3.3 场景

8 个手绘场景，只在 `stage` 镜头里画，作为物件后面的背景层。线条透明度 0.22–0.32，不填大面积颜色，不抢前景；都带同一条地面线 y = 930。

| `scene` | 画面 |
| --- | --- |
| `blank` | 只有地面线 |
| `podium` | 讲台和身后的白板轮廓 |
| `kitchen` | 墙面瓷砖线、吊柜、窗户 |
| `street` | 远处一排店面和路灯，人行道边线 |
| `lab` | 墙上的架子和烧瓶轮廓、操作台边线 |
| `office` | 窗户、书架、挂钟 |
| `outdoor` | 远山、太阳、几朵云 |
| `workshop` | 工具墙、挂钩、木地板线 |

- 场景元素避开画面中央 x 560–1360、y 360–930 这块主要表演区，只在两侧和上方。
- `shot.scene` 只能写在 `stage` 镜头上；不写时用 `world.scene`。

### 3.4 L0 流程

- `SKILL.md` 的步骤里，在\"写分镜\"之前加一步\"定视觉世界\"：根据主题选比喻、风格包和场景，按推荐表提服装和配音，写进 `world`。
- `分镜.md` 开头加一行\"视觉世界：<比喻>；风格 <style>；场景 <scene>\"，`docs.mjs` 检查它和 `world` 一致。
- 提示词包：每个镜头的提示词前面加上风格包和场景的中英文描述，外部视频模型也能画出同一个世界。

## 4. 物件（批次 1）

### 4.1 内置物件

`icons.mjs` 扩成约 60 个物件，文件名不变。原来 24 个图标的名字和画法都保留，`bullets`、`flow` 里的 `icons` 照常可用，也能用新增的物件。

| 分组 | 物件 |
| --- | --- |
| 原有 24 个 | `browser`、`server`、`database`、`cache`、`clock`、`doc`、`user`、`phone`、`cloud`、`lock`、`key`、`chart`、`check`、`cross`、`warn`、`bulb`、`gear`、`network`、`folder`、`image`、`search`、`money`、`plane`、`globe` |
| 家居厨房 8 个 | `fridge`、`cup`、`pot`、`table`、`chair`、`door`、`window`、`trash` |
| 商店街道 6 个 | `shop`、`cart`、`box`、`wallet`、`piggybank`、`house` |
| 交通物理 6 个 | `car`、`truck`、`rocket`、`battery`、`magnet`、`scale` |
| 科学教育 6 个 | `beaker`、`microscope`、`book`、`whiteboard`、`brain`、`heart` |
| 办公信息 6 个 | `laptop`、`mail`、`megaphone`、`calendar`、`stamp`、`clipboard` |
| 小件与符号 4 个 | `package`、`ticket`、`shield`、`hourglass` |

每个物件在代码里带一份元数据：

| 元数据 | 说明 | 例子 |
| --- | --- | --- |
| `height` | 在舞台上的自然高度，以小青身高 H（400 px）为单位 | `fridge` 1.08，`door` 1.15，`chair` 0.5，`box` 0.42，`cup` 0.15 |
| `aspect` | 宽高比 | `fridge` 0.55，`car` 2.2 |
| `layer` | 默认高度层（§5.2） | `fridge` 落地，`cloud` 空中，`cup` 放在台面上 |
| `anchors` | 交互锚点，物件局部坐标 | `handle` 把手，`top` 顶面中点，`seat` 座面，`front` 正面中心 |
| `states` | 支持的专属状态（§7.1） | `fridge`：`open`、`closed`、`full`、`empty` |
| `carry` | 能不能拿起来 | 自然高度不超过 0.45 H 且不是落地重物时可以 |

舞台上画的是大尺寸物件，线宽按尺寸缩放，但不细于小青身体线宽的一半；在 `bullets`、`flow` 里仍画成小图标。

### 4.2 物件文字

- 每个舞台物件可以带一个 `label`，不超过 8 字，36 px，画在物件上方 24 px；和标题带或空中物件冲突时改画在物件正面。
- `label` 也算画面关键词，参与 `VISUAL_NOT_IN_NARRATION` 检查。

### 4.3 自定义道具

内置物件不够用时，在 `world.custom_props` 里用几何图元拼一个：

```json
{ "id": "c_fishtank", "label": "鱼缸", "height": 0.5, "layer": "ground",
  "parts": [
    { "shape": "rect", "x": -0.9, "y": -0.5, "w": 1.8, "h": 1.5, "fill": "soft_accent" },
    { "shape": "circle", "cx": -0.3, "cy": 0.2, "r": 0.15, "fill": "yellow" },
    { "shape": "poly", "points": [[0.1, 0.2], [0.4, 0.05], [0.4, 0.35]], "fill": "yellow" },
    { "shape": "line", "points": [[-0.9, -0.3], [0.9, -0.3]] }
  ] }
```

- `id` 以 `c_` 开头，只用小写字母、数字和下划线，不和内置物件重名。
- 画布是 [-1, 1] 的正方形，y 向下；画布底边 y = 1 落在地面或台面上。`height` 是画布边长对应的高度，范围 0.1–1.5 H。
- 图元只有 4 种：`rect`（`x`、`y`、`w`、`h`）、`circle`（`cx`、`cy`、`r`）、`line`（2–6 个点的折线）、`poly`（3–8 个点的闭合多边形）。坐标都在 [-1, 1] 内。
- `fill` 只能写风格包的色键或 `none`；描边统一用 `ink`，经 `ink.mjs` 画成手绘线条。
- 每期最多 4 件，每件最多 12 个图元。锚点自动算：`top` 是图元外框顶边中点，`handle` 是朝向小青一侧的外框边中点，`front` 是外框中心；`height` 不超过 0.6 H 的有 `seat`（顶边中点）。
- 自定义道具只支持 §7.1 的通用状态，可以 `carry`、`hold_up`（`height` 不超过 0.45 H 时）、`push`、`pull`（落地时）、`sit_on`（有 `seat` 时）和 `react`，不支持 `open` 和 `draw`。
- 这些数据和讲稿一样视为不可信输入：只按上面的白名单渲染，数值全部截断到范围内，`check.mjs` 对越界、超量、未知字段报错（`CUSTOM_PROP_INVALID`）。

## 5. `stage` 舞台版式（批次 1）

### 5.1 写法

```json
{ "id": "sh05", "section": "s02", "sentences": [0, 1], "layout": "stage",
  "host": { "expr": "curious", "gesture": "idle" },
  "visual": { "template": "stage", "data": {
    "heading": "家门口的冰箱",
    "objects": [
      { "prop": "fridge", "label": "缓存", "at": "mid-left", "state": "closed" },
      { "prop": "shop", "label": "服务器", "at": "right", "size": "sm" }
    ],
    "links": [{ "from": 0, "to": 1, "style": "dashed", "label": "很远" }]
  } },
  "cues": [{ "sentence": 1, "do": "move", "target": 0 }],
  "note": "缓存就在手边，服务器在远处" }
```

- `layout: "stage"` 和 `visual.template: "stage"` 必须同时出现；`stage` 镜头必须写 `host`，和 `host-left` 一样。
- `host` 可以多写一个 `at`（槽位或比例），指定小青的起始站位；不写时见 §5.3。
- `objects` 1–5 个，`links` 0–4 条，`heading` 可选、不超过 14 字。
- 物件就是这一镜的元素：`objects[i]` 的序号就是 `reveal`、`highlight`、`move`、`tap` 和各种互动 cue 的 `target`。`links` 不是元素。

### 5.2 站位、高度层和尺寸

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `at` | `left`、`mid-left`、`center`、`mid-right`、`right`，或 0.08–0.92 的比例 | 物件中心的水平位置；五个槽位分别是 x 240、600、960、1320、1680 |
| `layer` | `ground`、`mid`、`air` | 不写时用物件默认值。`ground`：底边贴地面线；`mid`：放在同一槽位落地物件的顶面上（桌上的杯子），同一槽位没有落地物件时底边在 y 762（小青胸口高度）；`air`：底边在 y 470 以上（云、飞机、招牌） |
| `size` | `sm`、`md`、`lg` | 自然高度乘 0.75、1、1.3 |
| `state` | 物件支持的状态 | 起始状态，不写时是 `normal`（有 `closed`、`full` 这类默认状态的物件用默认状态） |

### 5.3 自动排版

由 `stage.mjs` 的纯函数完成，`check.mjs` 和渲染器调用同一个函数：

1. 按 `at` 算出每个物件的中心和自然尺寸。
2. 同一高度层里相邻物件的间隔不少于 40 px，重叠时向两侧推开；舞台范围是 x 120–1800。
3. 给小青留一条宽 200 px 的站位：优先用 `host.at`；没写时用上一个出镜镜头结束时的 x；那里被物件占了，就选离它最近的空位。
4. 放不下时整体等比缩小，最小到 0.6 倍；还放不下，`check.mjs` 报 `STAGE_CROWDED`，请 agent 减少物件或拆镜头。
5. 标题带 y 48–150；空中物件的顶边不高于 y 160；物件和文字都不进字幕区（y 950 以下）。

### 5.4 小青在舞台上

- 现有的走位、指、拍都直接作用在物件上：`move` 走到物件靠空位一侧、手够得着的地方；`point` 和 `lean_in` 的视线对准物件中心；`tap` 拍在物件的 `front` 锚点上。
- 前后层次：场景 → 物件 → 小青 → 手里拿着或抱着的物件 → 文字和字幕。
- 版式切换：`stage` 和 `host-left` 共用地面线，小青保持 x 不动，物件和卡片交叉淡化；`stage` 和 `full` 之间沿用现在 `host-left` 和 `full` 的走出、走入。
- 遮挡：互动以外的时间，小青的身体外框不和物件外框重叠，QA 报 `HOST_OBJECT_OVERLAP`；互动进行中允许重叠。

### 5.5 新模板 `timeline` 和 `cycle`

可以用在 `host-left` 和 `full` 里。

| 模板 | `data` | 文字上限 | 元素 |
| --- | --- | --- | --- |
| `timeline` | `items`：2–5 个 `{time, label, icon?}` | `time` 6 字，`label` 8 字 | 每个时间点 |
| `cycle` | `items`：3–5 个 `{label, icon?}` | 每个 6 字 | 每一步（连同指向它的弧形箭头） |

- `timeline` 是一条横向手绘时间轴，标签上下交替；`cycle` 是一圈首尾相接的弧形箭头。

## 6. 同台互动（批次 2）

### 6.1 互动 cue

8 个新的 `do`，`target` 都是物件序号：

| `do` | 动作 | 适用物件 | 结果 |
| --- | --- | --- | --- |
| `open` | 握住 `handle`，拉开门或掀开盖子，0.6 秒 | 有 `open` 状态的物件 | 物件变成 `open` |
| `carry` | 拿起物件，之后的 `move` 一起带走；`target: "none"` 放下在脚边 | 可拿起的物件 | 物件跟着手走 |
| `push` | 身体前倾抵住物件侧面，推远 160 px | 落地物件 | 物件位置改变，带一点回弹 |
| `pull` | 身体后仰拉住 `handle`，拉近 160 px | 落地物件 | 同上 |
| `hold_up` | 双手把物件举过头顶给观众看，1.5 秒后放回原处 | 可拿起的物件 | 一次性 |
| `draw` | 站到物件前面快速写画，1 秒 | `whiteboard`、`clipboard`、`doc`、`book` | 物件的 `label` 逐字写出来 |
| `sit_on` | 走到 `seat` 坐上去，坐到下一次 `move` 或互动为止 | 有 `seat` 的物件（`chair`、`box`、`table` 等） | 骨盆对准座面 |
| `react` | 面朝物件，按物件当前状态做反应：坏的状态（`expired`、`broken`、`crossed`、`empty`）往后一缩，好的状态举手欢呼，0.8 秒 | 任意 | 一次性，不走动 |

- 小青离锚点超过手臂长度（0.35 H）时，先自动走过去再做；自动走近不计入 `MOVE_TOO_MANY`。
- 手用现有的两节反向求解对准锚点（`motion.mjs` 的 `solveTwoBoneIK`），物件跟着手的位置走。
- 同一时间只能抱一个物件；`carry` 时手里的道具（`prop`）自动放下。
- 物件和动作不匹配时（例如 `open` 一个没有 `open` 状态的物件），`check.mjs` 报错 `INTERACTION_INVALID`，并列出这个物件支持的动作。

### 6.2 状态变化：`state` cue

```json
{ "sentence": 2, "at": "过期", "do": "state", "target": 0, "value": "expired" }
```

- cue 新增可选字段 `value`；`do` 为 `state` 和 `send` 时必填。
- 状态切换带 0.25–0.35 秒的手绘动效：门转开、红叉两笔划出、印章落下弹一下、数字翻动。
- `stage` 物件可以用 §7.1 的全部状态；`bullets`、`flow`、`compare`、`bars`、`timeline`、`cycle` 的元素只能用通用状态。

### 6.3 沿线运送：`send` cue

```json
{ "sentence": 3, "do": "send", "target": 0, "value": "package" }
```

- 让一个小物件（`package`、`doc`、`mail`、`ticket`、`money`、`key` 或可拿起的自定义道具）沿箭头飞过去，0.8 秒，到达时终点物件轻轻一弹。
- 在 `stage` 里 `target` 是 `links` 的序号；在 `flow` 里 `target` 是箭头指向的节点序号（从 1 开始）。

### 6.4 自动配合

- 新物件 `reveal` 时，小青没有别的动作就转头看它 0.6 秒。
- 物件被 `highlight` 或换状态时，小青空闲就点一下头。
- 自动挑选动作时跳过和上一句相同的保持型动作（H 阶段已有，扩展到 `stage`）。

### 6.5 自检

`match.mjs` 新增两个警告，并收紧一条：

| 代码 | 条件 |
| --- | --- |
| `NO_INTERACTION` | `stage` 镜头里没有任何互动 cue，也没有 `tap` |
| `GESTURE_REPEAT` | 同一镜头里相邻两次显式写出的动作（含 `host.gesture`）相同；或相邻两个出镜镜头的 `host.gesture` 相同、后一个镜头又没有别的动作 cue |
| `STATIC_STRETCH` | 上限从 8 秒改为 4 秒。看过批次 2 的样片后再调 |

`storyboard.md` 加\"动作卡\"写法：每个互动写清句意、动作、对象、之前和之后的状态，再用删除测试检验（去掉它观众会不会少懂）。

## 7. 状态清单

### 7.1 状态

| 类别 | 状态 | 样子 |
| --- | --- | --- |
| 专属：开合 | `open`、`closed` | 门扇、盖子转开或合上 |
| 专属：满空 | `full`、`empty` | 里面的东西出现或消失 |
| 专属：锁 | `locked`、`unlocked` | 锁扣合上或弹开 |
| 专属：新鲜 | `fresh`、`expired` | 闪光；或颜色变暗、旁边冒出红色小钟 |
| 专属：亮灭 | `lit`、`off` | 屏幕或灯亮起，或变暗 |
| 通用 | `normal`、`active`、`dim`、`crossed`、`stamped`、`broken` | 原样；外圈发光；变淡；红叉；盖章；裂纹 |
| 通用：计数 | `count:<值>` | 右上角的数字徽标，最多 4 个字符 |

每个物件支持哪些专属状态写在它的元数据里，`references/world.md` 列出完整的表。写了物件不支持的状态时，`check.mjs` 报错 `STATE_UNSUPPORTED`。

## 11. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 60 个物件画得参差不齐 | 先出物件速查表（和小青速查表同样的导出方式）给 owner 看，统一线宽、比例和色键再进模板 |
| 轻量模型乱写坐标或状态 | agent 只写槽位和状态名；排版和锚点由代码算；不支持的组合由 `check.mjs` 报错并给出可选项 |
| 舞台太挤、文字压物件 | 自动排版有最小间隔和缩小下限，放不下就报错让 agent 拆镜头 |
| `STATIC_STRETCH` 收紧到 4 秒后警告太多，agent 为凑数加无意义的 cue | 只是警告；动作卡要求删除测试；看过样片后再调上限 |
| `storyboard.md` 超出 10 KB | 新规则写进 `world.md`，`storyboard.md` 只加链接 |
| 渲染变慢 | 场景层每镜画一次进缓存；物件按状态缓存 SVG；用 540p 预览测渲染时间，比 H 阶段慢 30% 以上就优化 |
