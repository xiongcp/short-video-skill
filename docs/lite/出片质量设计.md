- 日期：2026-11-24

- 关系：修订 [轻量化Skill计划书.md](轻量化Skill计划书.md) 的 D3、§4.1 媒体规范、§4.7–4.13 和 P2/P3 分期；与计划书冲突的地方以本文为准，其余仍按计划书执行

## 1. 背景与目标

owner 对出片提了六点要求：人物更细致；帧率更高；内容与画面高度匹配；过渡动画平滑；给出最新设计；优化 md 文件和官网。

梳理现状后发现的问题：

| 方面 | 现状 | 问题 |
| --- | --- | --- |
| 出片链路 | 只有 L0（讲稿、分镜、提示词包）；L1 本地渲染还没写 | 旧 Studio 演示片 `output/default-host-demo.mp4` 是 1080p30、13 秒，右侧图解区是空白方框 |
| 主持人 | 代码画的扁平矢量，导出成 4 张 820×900 身体 PNG 加 1 张面部图集（每格 180×172），口型只有 3 档 | 没有阴影和高光，头发和衣服不分层，手臂是胶囊形状；换手势要整张换图，动作不连续 |
| 帧率与动画 | 媒体规范锁定 30/1 fps；只有表情切换有 3 帧淡化 | 推拉、转场和口型都不够顺 |
| 转场 | 镜头片段之间硬切 | 画面跳变 |
| 时间对齐 | cue 最细只能落在句首 | 口播说到"三零四"时，画面上的 304 可能早出现或晚出现好几秒 |
| 语义 | 没有检查画面关键词和口播是否对得上 | 画面可能在讲别的，或者过于空泛 |
| L0 外部模型 | 每镜一条文生视频提示词，参考图只有一张正面立绘 | 生成的镜头容易和分镜、口播对不上，人物长相也不稳定 |
| 官网 | 不存在（仓库里没有网页，GitHub Pages 没开） | 没有对外的介绍页 |

## 2. 已确认的决定

| # | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 官网 | 在仓库里新建 `site/` 单页静态落地页，用 GitHub Pages 发布 |
| Q2 | 帧率 | 默认 60fps，可选 30；`--preview` 用 540p30；120 秒成片的渲染预算放宽到 ≤ 8 分钟 |
| Q3 | 人物细节 | 用代码重绘为分层矢量部件骨架（约 20 个部件），渲染时直接光栅化矢量 |
| Q4 | 匹配度 | 四类都要处理：时间对不上、画面在讲别的、外部模型出图跑偏、主持人表演不贴合 |
| Q5 | 转场 | 以同元素补间为主（类似 PPT 平滑切换），没有共同元素时缓动叠化 |
| Q6 | 总体方案 | 方案 1：连续时间矢量动画 + 镜头开头的转场补间 + 关键词锚点 + 按镜头并行渲染，仍用 resvg + FFmpeg。没有选"保留 PNG、预烘焙动作帧"（做不出连续动作，体积超预算），也没有选"无头浏览器录制"（要带 150 MB 以上的 Chromium，违背计划书 D4） |
| Q7 | 本次范围 | 交付本设计文档；md 文件优化和官网本次实现；渲染器代码（P2/P3）以后按本文另写实施计划 |

计划书中被修订的决定：

- **D3**（静态立绘 + 表情切换，按音量开合口型）→ 改为矢量部件骨架，表情和手势做参数补间，口型连续开合。
- **§4.1 目标 5**（30/1 fps）→ 改为默认 60/1，可选 30/1。其余规格不变：1920×1080、H.264 yuv420p、AAC 48 kHz、半开帧区间 `[start, end)`。
- **§7.3 渲染耗时**（≤ 5 分钟）→ 120 秒、60fps 成片 ≤ 8 分钟；30fps 仍为 ≤ 5 分钟。

## 4. 架构与数据契约

### 4.1 L1 管线

```
project.json ─► check/validate ─► tts（按句合成 + 逐词时间）─► timing（锚点 → 毫秒）
   ─► scene（按连续时间 t 求每个元素的状态，含镜头开头的转场）
   ─► 多 worker 并行：SVG → resvg → RGBA ─► FFmpeg 按镜头编码 ─► concat 直接拼接
   ─► 整条混音与响度归一 ─► 封装 ─► qa
```

- **动画与帧率无关**：每个可动属性都是 `state(t)`，t 以秒为单位；最后才按 `settings.fps` 换成帧号。每帧音频采样数在 30fps 时是 1600，60fps 时是 800。
- **转场只占下一镜的开头**：镜头 n 的前 0.4 秒（60fps 下是 24 帧）从镜头 n−1 的结束状态补间过来。上一镜的结束状态由 `project.json` 完全确定，所以渲染器能在镜头 n 里重画它，不需要读上一镜的视频。每个镜头仍然独立渲染、独立缓存，拼接时不重新编码。
- **缓存键**：哈希（镜头 JSON + 所含句子音频的哈希 + 上一镜结束状态的哈希 + fps + 分辨率 + 模板、骨架、渲染器的版本号）。不含绝对帧号，所以前面的镜头变长或变短时，后面镜头的片段照样复用。

### 4.2 新模块

`scripts/lib/` 下新增 `ease`（缓动曲线）、`timing`（锚点和估时）、`rig`（主持人骨架）、`icons`（内置图标）、`scene`（状态求值与转场）；保留计划书已有的 `timebase`、`captions`、`mouth`、`templates`、`frame`、`encode`、`qa`、`providers`。skill 目录预计约 32 个文件，在 45 个的上限以内。

### 4.3 `project.json` 的新增字段

只做向后兼容的新增，不改已有字段名和枚举值，旧项目照样有效，`version` 仍为 1。

| 字段 | 类型 | 说明 | 缺省 |
| --- | --- | --- | --- |
| `settings.fps` | `30` 或 `60` | 成片帧率 | 60 |
| `cue.at` | 字符串 | 句子里的关键词，必须是该句原文的子串；有多处时取第一处，要换位置就写长一点 | 落在句首（与现在一致） |
| `shot.transition` | `"cut"` | 故意硬切，用来制造冲击 | 自动：有同名元素就做同元素补间，没有就叠化 |
| `visual.data.icons` | 字符串数组 | 只用于 `flow` 和 `bullets`，长度等于元素数，取值来自内置图标名 | 不配图标 |

`cue.at` 按讲稿原文写。讲稿里数字是按读法写的，例如 `"at": "三零四"`，不写 `"304"`。

### 4.4 逐词时间：`audio/timing.json`

逐词时间是派生数据，放在项目的 `audio/timing.json`，不写进 `project.json`，以免影响人工编辑：

```json
{
  "s02-1": {
    "file": "audio/s02-1.wav",
    "duration_ms": 3420,
    "speech": [80, 3310],
    "source": "provider",
    "words": [{ "text": "三零四", "start_ms": 1260, "end_ms": 1720 }]
  }
}
```

键是"段落 ID-句序号"。`source` 为 `provider` 表示 TTS 实测，为 `estimate` 表示按 §6.1 估算；`speech` 是去掉首尾静音后的发声区间。

### 4.5 新增自检（`check.mjs`）

| 代码 | 级别 | 触发条件 |
| --- | --- | --- |
| `ANCHOR_NOT_IN_SENTENCE` | 错误 | `cue.at` 不是该句原文的子串 |
| `UNKNOWN_ICON` | 错误 | `icons` 里有不存在的图标名，或者长度和元素数不一致 |
| `VISUAL_NOT_IN_NARRATION` | 警告 | 一个镜头的画面关键词全都和本镜口播对不上（判定方法见 §6.2） |
| `POINT_MISSING` | 警告 | `host-left` 镜头的某句口播含有指示词（"看右边""右边的""右侧""看这张图""看这里""看这儿""看这边""右图"），但那一句生效的手势不是 `point_right` |

前两项属于 schema 变更，随 P2b 实现；后两项只依赖现有字段，在 L0 规则修订时一并实现（见 §11）。

## 5. 主持人 v2

### 5.1 部件骨架

`assets/host/host.svg` 由代码绘制，约 20 个 `<g>` 分组，每组都有轴心：

- 头部：后发、侧发（左右）、前发、呆毛、头、耳、眉（左右）、眼（左右，各含眼白、虹膜、瞳孔、两个高光、上睫毛线、下睫毛线）、鼻、嘴、腮红
- 身体：颈、躯干（含外套、衬衫领、领结、纽扣）、上臂（左右）、前臂（左右）、手（左右）

部件 ID、轴心、关节角度范围、表情参数和手势姿态都写在 `assets/host/manifest.json` 里（文件名不变，内容改版）。`profile.json` 的表情名、手势名和 `prompt_lock` 保持不变。

原来的 `body-*.png` 和 `faces.png` 共 5 张，由 `host.svg` 和 `host-ref.png` 取代。`host-ref.png` 是给 L0 外部模型用的参考图：一张全身正面加 4 个表情头像，约 300 KB，由开发脚本从 `host.svg` 导出。`rights.json` 的 `usage` 保持 `pending`，只有 owner 能改。

用户想换自己的主持人时，只要提供部件 ID 相同的 SVG 和对应的 `manifest.json`、`profile.json`。

### 5.2 细节规格（验收逐项对照）

| 部位 | 要求 |
| --- | --- |
| 眼睛 | 虹膜用径向渐变，两个高光点；上睫毛线有粗细变化；下睫毛单独一条线 |
| 头发 | 后发、侧发、前发三层；一圈高光带；前发在额头投下阴影 |
| 衣服 | 外套翻领和侧面有阴影；画出衬衫领、领结的结和褶、纽扣、袖口 |
| 手 | 放松、指向、张开 3 种手型，画出手指 |
| 着色 | 两色赛璐璐（底色加一层阴影）；头发和肩膀加边缘光 |
| 描边 | 外轮廓粗、内部细节细，两种线宽 |

审美没法自动判定。P2a 先出一张 1080p 形象图请 owner 确认，确认后渲染器才使用新形象。

### 5.3 表情与手势：参数补间

- **表情**由一组参数描述：眉的角度和高度、睁眼程度、笑眼弧度、虹膜大小、嘴角曲线、腮红深浅。切换表情时，这组参数在 0.25 秒内缓动过去，五官是真的在变形。表情仍是 `explaining`、`focused`、`happy`、`curious` 四种。
- **手势**由肩、肘、腕的角度加手型描述。切换时角度在约 0.4 秒内缓动到位（easeOutBack，带一点回弹）；手型在动作中点切换，做 4 帧叠化。手势仍是 `idle`、`point_right`、`wave`、`emphasize` 四种。
- 原来 `curious` 导出时去掉的头部倾斜，现在由颈部轴心直接转出来。

### 5.4 口型与微表演

**口型**（纯 JS 处理 PCM，不用模型；逐音素口型仍不在范围内）：

- 开度：每帧取对应采样计算 RMS，用每句的 95 百分位做归一化，再做"快张慢合"的单极点平滑（张开约 30 ms，合上约 80 ms），得到 0–1 的连续开度。低于阈值时闭嘴，句间停顿时也闭嘴。
- 嘴形：用过零率区分扁嘴（如"衣""诶"，过零率高）和圆嘴（如"乌""哦"，过零率低），映射到嘴的宽窄参数。

**自动微表演**（渲染器根据音频和时间自动添加，Agent 不用写）：

| 动作 | 规则 |
| --- | --- |
| 呼吸 | 躯干缩放 ±0.8%，肩膀随之起伏，周期 4 秒 |
| 眨眼 | 间隔 3–6 秒随机，约 0.15 秒；偶尔连眨两次；种子是镜头 ID 加镜头内相对时间 |
| 点头 | 重读处（音量峰值超过阈值）头部下点约 2°，再弹回 |
| 歪头 | 问句末尾歪头约 6°，同时挑眉 |
| 头发 | 弹簧阻尼跟随头部的角速度；每个镜头从静止状态开始模拟，保证结果可复现 |
| 视线 | 默认看观众；有图解元素出现或做指向手势时，眼睛先看过去约 0.6 秒，再回到观众 |

**Agent 负责的大表演**：表情和手势选什么，用 cue 加 `at` 卡到具体的词上。`storyboard.md` 增加"句意 → 表演"对照表：

| 句意 | 表情 | 手势 |
| --- | --- | --- |
| 开场打招呼、结尾告别 | `happy` | `wave`（全片最多 2 次） |
| 提问、制造悬念 | `curious` | `idle` |
| 讲难点、提醒注意 | `focused` | `idle` 或 `emphasize` |
| 指向图解（"看右边""这张图"） | `explaining` | `point_right`，卡在指示词上 |
| 关键结论 | `happy` 或 `focused` | `emphasize`，卡在结论词上 |

### 5.5 版式切换

`host-left` 切到 `full` 时，主持人缓动滑出画面左侧，图解区同时放大铺满；反向切换时倒放。`full` 版式里照旧不出现主持人。

## 6. 匹配度

### 6.1 时间对齐

**逐词时间的来源**，按优先级：

1. TTS 返回的逐词时间戳（edge-tts、Azure、火山引擎、阿里云等接口提供）。
2. 估算：先用音量阈值切掉句首和句尾的静音，再把剩下的发声时长按权重分给各个字。权重为：汉字 1；阿拉伯数字按读出的字数算（`304` 读"三零四"，记 3）；英文单词按音节数的 0.8 倍；逗号、顿号、分号、冒号记 0.6，表示停顿。估算值在 QA 报告里标"估算"。
3. OpenAI 兼容的 `/v1/audio/speech` 不返回时间戳，只能走估算。

**用户提供整段录音（`import`）**：用 FFmpeg `silencedetect` 按句间停顿切开。切出的段数必须等于句数；对不上时停下来请用户确认，不硬猜。

**锚点换算**：锚点时间 = 句子起点 + 关键词的 `start_ms`。

| 事件 | 时机 |
| --- | --- |
| reveal 入场 | 锚点前 0.15 秒（60fps 下 9 帧）开始，0.35 秒内完成，说出这个词时正好落定 |
| highlight 强调 | 正好落在锚点上 |
| 表情、手势 | 锚点前 0.1 秒开始补间 |

**字幕**：一句一条；超过单行上限时按逗号切开，时长按逐词时间分配（没有逐词时间时按估算分配并标注）。`cue.at` 的关键词在字幕里同步变成强调色，和图解的高亮同时出现。

### 6.2 语义匹配

- **规则**（写进 `storyboard.md`）：一个镜头只讲一个意思；画面只表现此刻正在说的东西；口播里的关键数字用 `number` 或 `bars` 表现。
- **`VISUAL_NOT_IN_NARRATION` 的判定**：
  1. 把画面关键词和本镜口播都归一化：去掉标点；把中文数字读法换成阿拉伯数字（"三零四"→304，"三点五"→3.5，"一万"→10000）；字母转小写。
  2. 一个关键词只要有一个相邻两字的汉字片段，或者一个完整的数字或英文词出现在口播里，就算匹配。
  3. 一个镜头里的关键词全都不匹配时才警告。逐个关键词报警太吵：在 `cache-speed` 示例上会误报 9 条，多数是画面延续上一镜的节点，或者口播换了说法。
  4. 不检查 `title`，因为标题卡常常是在概括。
- **内置图标**：约 24 个线性图标，全部画在 `icons.mjs` 一个文件里：浏览器、服务器、数据库、缓存、时钟、文档、用户、手机、云、锁、钥匙、图表、对勾、叉、警告、灯泡、齿轮、网络、文件夹、图片、搜索、钱、飞机、地球。图标名是固定枚举，写进 schema。
- **布局**：模板按元素数量自动排布，填满安全区，画面上不出现大块空白。

### 6.3 外部模型与表演

外部模型出图跑偏的处理见 §10，主持人表演不贴合的处理见 §5.3–5.4。

## 7. 动画与转场

### 7.1 缓动与时长

不用匀速运动；除了故意的硬切，属性不跳变。

| 动作 | 时长 | 曲线 | 表现 |
| --- | --- | --- | --- |
| reveal 入场 | 0.35 秒 | easeOutCubic | 淡入，上移 24 px，从 0.96 倍放大到原尺寸 |
| highlight 强调 | 0.25 秒 | easeOutBack | 变成强调色，在 1 → 1.06 → 1 之间脉冲一次 |
| `flow` 箭头 | 0.4 秒 | easeInOutCubic | 描线生长 |
| `number` 计数 | 0.8 秒 | easeOutCubic | 从 0 计数到目标值 |
| `bars` 生长 | 0.6 秒 | easeOutCubic | 依次生长，每根间隔 0.08 秒 |
| `title` 出现 | 0.5 秒 | easeOutCubic | 逐字淡入，每字间隔 0.03 秒 |
| 镜头缓推 | 整个镜头 | easeInOutSine | 1.00 倍到 1.03 倍，背景做轻微视差 |

缓动曲线只有 `linear`（只用于时间轴本身）、`easeOutCubic`、`easeInOutCubic`、`easeOutBack`、`easeInOutSine` 五种，都写在 `ease.mjs` 里。

### 7.2 转场

- **同元素识别**：比较前后两镜元素的文字，包括节点名、要点、数字加它的标签、对比栏标题和标题。主持人永远算同一个元素。
- **同元素补间（0.4 秒，easeInOutCubic）**：
  - 两边都有的元素，平滑移动到新的位置、尺寸和颜色。
  - 只在上一镜有的元素，在前 0.2 秒缩小并淡出。
  - 只在新一镜有的元素，在 0.15 到 0.4 秒之间淡入。
- **没有共同元素**：0.3 秒缓动叠化。
- **版式切换**：主持人滑入或滑出，图解区同步缩放（见 §5.5）。
- **`shot.transition: "cut"`**：硬切。文字相同但含义不同的两个元素不该补间时，也用它断开。
- **锚点落在转场窗口内**：该元素并入转场一起入场，不会再闪一次。

## 8. 渲染与编码

### 8.1 性能

- **spike**（P2b 第一天）：实测一帧 1080p 的光栅化耗时，画面包括带渐变的 20 部件主持人、一个图解和一条字幕。超过约 40 ms 时改成分层：每个稳定区间里不动的层（背景、已经静止的图解元素）只光栅化一次，会动的层只渲染它的包围盒，再在 JS 里做 alpha 合成。
- **并行**：`min(CPU 核数 − 1, 8)` 个 worker，以镜头为单位分配，每个 worker 把原始帧写进自己的 FFmpeg 进程。
- **预算**：120 秒、60fps（7200 帧）≤ 8 分钟；30fps ≤ 5 分钟（Apple Silicon 笔记本）。
- **预览与样片**：`--preview` 输出 960×540、30fps；`--sample sh03-sh05` 按成片规格只渲染指定镜头。
- **帧区间**：先用累计毫秒计算，再在镜头边界处取整，误差不会逐镜累积；相邻镜头满足 `start_n = end_{n−1}`。

### 8.2 编码规格

| 项 | 取值 |
| --- | --- |
| 视频 | H.264 High，CRF 18，`yuv420p`，`-r 60`（或 30） |
| GOP | 2 秒（`-g` 为 2 倍帧率），关掉场景切换检测；每个片段以 IDR 开头，保证 concat 时不重新编码也能无缝拼接 |
| 色彩 | RGB 转 YUV 时显式指定 BT.709，并写入 `color_primaries`、`color_trc`、`colorspace` 标签（默认的 BT.601 会让颜色发灰、偏色） |
| 音频 | 整条混音，两遍 loudnorm 到 −16 LUFS、真峰值 −1 dBTP；AAC 48 kHz 立体声 192k |
| 封装 | `-movflags +faststart` |

## 9. QA（`svs qa`）

计划书 §4.13 的检查全部保留，帧率改为按 `settings.fps` 检查。新增：

| 检查 | 方法 | 判定 |
| --- | --- | --- |
| 同步 | 逐个比较带锚点的 cue：画面落定的时间与关键词开口时间之差 | 与 §6.1 的提前量相差 ≤ 1 帧；时间来自估算的标"估算" |
| 跳变 | 相邻两帧缩到 160×90 后比较亮度的平均绝对差 | 在没有安排切镜的地方超过阈值即为跳变（阈值初值 12/255，P3 用坏样例标定） |
| 卡顿 | 在安排了运动的区间里统计连续重复帧 | 连续 ≥ 3 帧完全相同即为卡顿 |
| 色彩 | ffprobe 读色彩标签 | 必须是 BT.709 |
| 匹配度 | 逐镜列出口播原文、画面关键词、两者的重合和警告 | 写进 `qa.md`，供人看 |

人工检查辅助：3×4 联系表；每个转场一条 6 帧的"转场条"；3 段口型抽检片段（开头、中段、结尾）。Agent 没有真正看过或听过的项，照旧标 `not_checked`；技术检查通过不等于审美通过。

## 10. L0 提示词包

这一节只改 `prompt-pack.md` 和 `storyboard.md` 的写法，不改 schema，本次实现。

- **默认流程**：先出首帧图，再图生视频。每镜写两条提示词：
  - **首帧图**：给图像模型。`host-left` 镜头上传主持人参考图（P2a 之前用 `body-idle.png`，之后用 `host-ref.png`），写清画风、人物锁定、构图和画面内容。
  - **运动**：给图生视频模型，只写画面怎么变化、镜头怎么动，不重复描述人物长相。
- **首尾帧**：平台支持首尾帧时（如可灵、即梦、Vidu、海螺），把下一镜的首帧图当作这一镜的尾帧，镜头之间自然衔接，人物也更稳定。平台不支持图生视频时，用合并后的文生视频提示词作为后备。
- **每镜新增两行**：
  - **本镜口播**：原文照抄，方便剪辑时核对画面与口播。
  - **节拍**：按 `check.mjs` 的估时写出关键动作的时间点，例如"约 2 秒说到'三零四'时，304 的卡片亮起"。为此 `estimates.shots` 的每一项新增 `starts`，列出本镜每句的起始秒数，Agent 照抄，不用自己数字。
- **生成后逐镜验收**：人物和参考图一致；画面中没有文字；动作对上节拍；首尾能接上。不合格就重新生成，每次付费生成都记进 `jobs`。
- **自检**：`check.mjs` 现有的提示词包检查（`### shNN` 标题逐镜对应、确认状态行）不变。

## 13. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 带渐变的 20 部件主持人光栅化太慢 | spike 先测；超标就分层合成，主持人只渲染包围盒；必要时把渐变换成两色平涂 |
| 估算的逐词时间不准 | QA 标"估算"；`providers.md` 推荐带时间戳的 TTS；误差主要影响长句，`script.md` 已限制每句 ≤ 30 字 |
| 中文数字归一化遇到少见读法 | `VISUAL_NOT_IN_NARRATION` 只是警告；单元测试覆盖常见读法（逐位读、带单位、小数、百分比） |
| 文字相同但含义不同的元素被误补间 | 用 `shot.transition: "cut"` 断开 |
| 头发弹簧在镜头边界不连续 | 每镜从静止开始模拟，转场补间期间以骨架姿态为主，弹簧幅度小，肉眼不可见；P3 转场条人工抽检 |

| 过零率口型在嘈杂录音上不稳 | 先对音频做高通和降噪预处理；QA 口型抽检 |
| edge-tts 等免费服务的商用条款不明 | `providers.md` 注明"商用前核对条款"，由 owner 决定 |
