# 验收计划与发布判定

简体中文 · [English](acceptance.en.md)

适用范围为 1–3 分钟短片与目标 8 分钟节目。本计划细化既有[需求验收矩阵](../../evals/acceptance.md)。运行入口和当前结果见[交接状态与证据](交接状态与证据.md)。实片中允许的静止阅读、停顿或黑场需由导演登记镜头、具体帧区间和原因。

## 1　由谁验，依据什么材料

| 证据等级 | 验收对象 | 可签发的结论 |
| --- | --- | --- |
| CONTRACT | 固定版本的 Schema、策略、纸面分镜、正反例 | 合同与设计一致 |
| FIXTURE_MEDIA | 可重建的图案/色块与音调，经真实编码、解码得到的 MP4 | 媒体技术检查在这些文件上有效 |
| RUNTIME | 实际项目 API、数据库、工作台、缓存和 Worker，在登记环境执行 | 某个运行时行为达标 |
| PRODUCTION / HUMAN | 真实来源、批准角色与配音、完整节目、授权审核人 | 某个具体版本的节目通过相应人工关口 |

每次运行分配一个 run_id。每个用例记录 PASS、FAIL、BLOCKED 或 NOT_RUN。FAIL 指已执行且不符合预期，BLOCKED 指已有具体依赖阻塞，NOT_RUN 指尚未执行。跳过项、夹具替身、人工观察均在等级栏标记。缺证据的条目不可签为 PASS。单项通过不会自动改动项目发布状态。

## 2　离线起点与媒体命令

在项目根目录运行，Python 需有 `evals/requirements.txt` 的依赖。媒体校准还需可用的 ffprobe，生成测试素材需要 FFmpeg 支持 libx264 与 AAC。对一部实际节目执行技术验收时使用其真实文件路径。

```sh
python3 -B evals/check_design.py
python3 -B -m unittest discover -s evals -p 'test_*.py' -v
python3 -B evals/check_design.py --media renders/final.mp4 --profile short --target-seconds 120
python3 -B evals/check_design.py --media renders/final.mp4 --profile standard8
```

第三条用于严格 120 秒，第四条使用 450–510 秒窗口。精确要求 8 分钟时追加 `--target-seconds 480`。媒体结果为 JSON。退出码 0 表示所测技术项通过，1 表示媒体缺陷或无法解码，2 表示调用参数或环境需处理。全绿报告仍须和审核记录、证据索引及归档清单一起使用。

| 编号 | 操作与判定 | 证据 | 本轮状态 |
| --- | --- | --- | --- |
| C00 | 运行架构检查及既有 11 项回归。两分钟样例 14 镜共 3,600 帧，长片 7 章 34 镜共 14,400 帧，图和契约检查通过 | CONTRACT · 两组示例与命令日志 | 已实测，见交接状态 |
| C01 | 对本机生成的 MP4 逐帧解码，检查容器、分辨率、编码、像素格式、30 fps 时间格、48 kHz 音轨、音画覆盖与片长。插入半帧抖动、去掉音轨或换成代理尺寸应失败 | FIXTURE_MEDIA · TDD 红绿记录、关键校准文件哈希及 JSON 输出 | 已实测，见交接状态 |

技术规格使用一条节目画面流，封面图排除，选默认音轨或首条音轨。半开区间由解码帧数推导，视频第 i 帧应在 i/30 秒，允许封装时间基舍入。音轨声明和解码样本的起止相对视频首尾的误差至多一个视频帧，以容纳 AAC 填充。相邻音频块的时间戳增量与上一块采样时长逐对核对，容差取一个音频采样和一格音轨时间基中的较大值。每份结果都附输入媒体的 SHA-256。探针字段的原始语义见 [FFprobe 官方手册](https://ffmpeg.org/ffprobe.html)。

## 3　运行时与内容用例

以下 A01–A16 均为交接后的实测任务，初始状态 NOT_RUN。表中的 PASS 条件同时适用于返修后的重验。每行指定的夹具均为实施时生成、登记或由所有者提供。

| ID / 任务 | 准备、执行与故障注入 | PASS 条件及最少证据 |
| --- | --- | --- |
| A01 环境与薄切片 · T01 | 新项目运行 doctor，记录引擎、字体、解/编码、图形后端和许可清楚的角色夹具。用本地 WAV、主持人层和图解做 10–15 秒有声技术片。移走测试字体再跑 | 正例可播放，帧数等于时间线。负例指明缺失字体或能力。留 doctor JSON、探针、首中末帧、WAV、环境锁。技术片长度单列，不套用短片 60 秒下限 |
| A02 状态和权限 · T02 | 两次提交相同事件，再提交同键不同内容、旧 revision、伪造审核人、过期 G2 和草稿导出。用认证的人类测试会话补齐对应版本决定 | 重放同键只生一个事件，冲突返回当前版本，未获准调用次数为零。G4/G5 分别绑定媒体和清单。留 SQLite 记录、审计及 UI 回执 |
| A03 预算与未知回执 · T03 | 给测试项目配置 100 个最小货币单位上限，并发请求两次各预留 70。让供应商测试端在接单后丢回执、重启服务再对账 | 最多预留一次 70，有效余额 30。UNKNOWN 保留预留，按原键查询，结算恰一次。无查询能力时保留待核验。留请求计数、账本和恢复日志，使用模拟供应商时标明范围 |
| A04 来源与脚本 · T04 | 以缓存主题或既有稿件启动。给一条过期来源、一对冲突材料及一条无依据断言，审核时要求缩短一个段落 | 原段落 ID 可追溯，关键论点均有状态、定位与限定。删除或限定未获支持的结论后由人批准 G1/G2。留来源卡、脚本 diff 和批准哈希 |
| A05 录音、对齐和口型 · T05 | 导入一段真实中文 WAV，包含 b/p/m、英文缩写、数字、停顿。校正一个错音和一个词锚，另测分片相对时间归零 | 保留原采样坐标、词典/音色版本和校正来源。只重做相关段落，字幕及嘴型一起更新。至少 100 个手标锚点，报告中位及 nearest-rank P95（升序第 ceil(0.95n) 项）。以 80/150 ms 作初测目标，由所有者记录校准决定 |
| A06 原创产物与风格 · T06 | 同一主持人在深、浅、棋盘三底，正面/批准侧角、闭唇和指向极值各出图。用图解把一项数据放大，故意提供不足像素的底图 | 无可见发丝白边、衣袖接缝、身份漂移或错误数据。低清底图能被定位，所有用到的资产有版本和使用范围。留角色包索引、参考对照、三底截图和人类决定 |
| A07 导演与编译 · T07 | 编译短片与长片样例的已对齐副本。加入同词复现、2399/2400 采样共享边界、悬空 cue、越界局部高亮、不可用动作、依赖环 | 符合条件的边界分别为第 1/2 帧，引用可追溯，帧从 0 连续覆盖到末端。反例报告镜头号及字段并阻断正式编译。留 DSL、已编译快照与拒绝报告 |
| A08 烘焙、渲染确定性 · T08 | 用批准的 Rig 做挥手、闭唇和转头。镜头取帧顺序改成末帧、首帧、中间帧，再改变 worker 顺序 | 固定环境下同一局部帧的无损 RGBA 哈希一致。明确依赖前镜末态的镜头使用其哈希，独立镜头可单独渲染。留参数、种子、像素差和首尾帧 |
| A09 崩溃与缓存 · T09 | 长片第 4 章中断，分别模拟只写临时文件、已重命名未登记、已登记后损坏。重启后与干净的全量运行比较 | 从有效检查点恢复，已验证的镜头无新增生成调用，损坏项重新产出。最终时间线、逐镜内容及音频采样可复核。留旧新缓存键、作业事件与章检查点 |
| A10 自动 QA · T10 | 注入一个中间帧的字幕撞框、一帧闪白、意外黑场、长静止和无音频。另保留已声明的静止读图段 | 硬缺陷定位到镜头及绝对帧区间，标注的停留保留理由。联系表有 12 个带时间码的定位格，单帧缺陷由逐帧检查发现。留异常帧、波形、包围盒与报告 |
| A11 主观画质和样片 · T06/T10 | 相同脚本、配音、规格比较基线与升级样片。打乱 A/B 展示顺序，完整听看 20–30 秒，逐项评价身份、演技、图解、阅读和节奏 | 记录哪些镜头改善/退步与原因，关键缺陷关闭，G3 由人签。历史素材缺失时可另制受控基线并注明，旧版实片对比保留未测。留两段样片、联系表和意见 |
| A12 返修范围 · T09 | 分别改字幕色、单镜表情及第 4 章缩短 10 秒。提前保存修前镜头哈希、调用统计与 G1–G5 | 字幕改动的 TTS/图像/视频生成及角色烘焙计数全为 0。表情只影响该镜与显式末态依赖。未重新分配时新章界为第 7,800 帧、全片 470 秒。留 ChangePlan、diff 和实际调用日志 |
| A13 无头交付、签收与归档 · T11（方案 A） | 用 CLI `trace` 核对一条来源、`revise` 改一个 cue、播放样片并查看 `deliverables/review-report.html`，走 G3–G5。换掉清单中一个字节再打包，将完整包解到新目录重新打开 | 旧签名对变化清单失效。新包中 MP4、SRT、WAV、来源、资产、QA、账本和审批逐件可核原哈希，恢复后可逐镜编辑。留 CLI 操作记录、manifest、归档收据及还原报告 |

## 4　节目级与可选路线

A05 和 A10 均留原始人声、成片混音和测量区间。A10 记录整片综合响度（LUFS）、最大真峰（dBTP）和非预期静音的位置。每个发布目标在 G3 前登记允许值与版本，QA 按已登记范围判定，缺目标则列为待确认。A11 在手机扬声器和耳机上回听一段浓密图解及一段停顿，记录是否有背景声遮词、错音或刺耳接缝。技术校准片中的纯音用于验证媒体轨道。

A11 的审片表逐镜填写五项观察。跨镜脸型和服装能否对上，重点词落下时嘴型和手势是否同步，指向的图形是否正确，文字在移动端能否读完，以及切镜后能否跟上讲解。每项记录“改善／持平／退步”、两版时间码和原因。退步项由所有者标为必改或接受并说明理由，必改项清零后方可签 G3。缺少可比旧样片时，只能记录本版的可用性，历史画质改善保留待验。

| ID / 任务 | 运行环境与操作 | PASS 条件及所需证据 |
| --- | --- | --- |
| A14 短片生产 · T12 | 分别制作 60、120、180 秒三种规格的可解码节目输出，至少一支使用真实主题、来源、配音、原创角色并走全流程 | 对应 1,800、3,600、5,400 帧。真实节目另有 G1–G5、完整回看、可重开包及实支，标记其余两支的实际素材等级。存媒体报告、WAV/SRT 和签收 |
| A15 长片生产 · T12 | 连续制作三期不同主题或不同实质内容的约 8 分钟节目，沿用同一批准角色包。至少一期重启并做跨章返修 | 每期处于批准窗口，指定精确 480 秒者为 14,400 帧。逐期有章口连续性、完整母版、人工回看、单片成本、冷/热耗时与归档还原。保留三个独立 run_id |
| A16 可选生成插镜 · T13 | 默认配置请求插镜，再以明确启用、授权素材、单镜限额运行一个 driving 片段。模拟超额及提交未知并试行回退 | 默认新增付费调用为 0。启用时批准候选与入口/出口帧、身份、镜头时长一致，超额阻断、UNKNOWN 不双扣，程序图解回退可审。没有真实渠道时此行保持 NOT_RUN 或 BLOCKED |

## 5　证据目录与放行签字

每次正式运行存入 `evidence/runs/<run_id>/<case_id>/`。最小记录包含 case_id、task_id、run_id、status、evidence_level、环境/工具版本、命令及退出码、输入快照/媒体哈希、实测观察、问题列表、证据相对路径、审核人或待审原因。敏感密钥、原始认证头和私有来源全文不入日志。

阻断项包括引用或素材缺失、严重事实错误、越出约定片长、解码或安全区硬缺陷、过期批准和不可对账的重复收费。记录原因、负责任务、修复后的版本与复查用例。美术意见和阅读节奏按帧留存，由内容所有者接受或退回。G4 复看完整成片与 QA，G5 核对打包清单。A01–A15 与真实人审齐备才可签为生产验收通过，未启用的 A16 单独登记。
