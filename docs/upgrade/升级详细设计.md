## 2　从指令到可编辑工程

入口 `skills/topic-to-video/SKILL.md` 读取项目默认值、片长档和模式。单个编排器持有任务、费用和审批状态。13 个 Skill 通过已登记对象协作。9 个执行适配器仍以 `tools/*/contract.yaml` 为接口，媒体验收命令独立运行于 `evals/`。后续适配器接入实际宿主后才能记录其运行证据。

| 环节 | 外部可见产物 | 硬约束及失败行为 |
| --- | --- | --- |
| 主题、研究、讲稿 | TopicBrief、EvidenceSet、ScriptDocument、来源卡 | 每个关键论点回到来源和定位，争议标记或删改。已有稿件保留原段落映射。正式语音绑定 G2 |
| 配音与导演 | WAV、AudioManifest、Alignment、Storyboard | 保存词的原始采样位置。区分估时 planned 与实测 aligned。输入缺失时返回对象 ID |
| 美术与编译 | CharacterActionPlan、ScenePlan、CompiledTimeline | 固定资产及版本，解析能力表、字体、图例、可达的 gaze/cue，所有镜头连续覆盖成片 |
| 渲染与返修 | 透明层、镜头片段、ChapterCheckpoint、ChangePlan | 同一局部输入可复用。提交未知的付费任务先对账。跨章姿态变化重算确有依赖的镜头 |
| 审核与交付 | QAReport、ExportManifest、FinalPackage | G3 放行正式全片，G4 绑定母版和 QA，G5 绑定本次文件清单。草稿保留水印和未审清单 |

宿主写操作带 project_id、expected_version 与 idempotency_key。SQLite 事务记录新版本、事件及依赖边。实物先写临时文件，核验后在同文件系统原子归位，再提交索引。启动时识别半成品、失联任务与无实物索引。发布资产保留旧哈希，生成引擎只访问当前项目登记且已授权的资产。代理提交的审核人字段不能替代认证的人类会话。

| 项 | 1–3 分钟短片 | 约 8 分钟节目 |
| --- | --- | --- |
| 时间合同 | 60–180 秒，未指定时 180 秒。60 / 120 / 180 秒对应 1,800 / 3,600 / 5,400 帧 | 目标 480 秒，即 14,400 帧。约定窗口暂取 450–510 秒，即 13,500–15,300 帧 |

| 样片 | 缓存示例 14 镜，取 [240,900) 共 22 秒，包含请求图解与主持人 | 订单示例 7 章 34 镜，取 [0,180)、[5580,5880)、[7950,8190)，共 24 秒 |
| 锁片与返修 | 每段对齐后锁镜头，短片完整回看 | 每章保留进出状态、声音参考、前后尾帧及恢复点。G4 播完整母版 |
| 播放与画幅 | 两档默认 1920×1080 横屏、30 fps、48 kHz。竖屏需另建布局与安全区 | 同左。导出章节起点由最终编译帧推导 |

制作同题双版时，两版各建 project_id、脚本、目标时长及审核链。来源、批准角色与基础图解可通过本项目登记复用底层内容哈希。短版删掉次要论证并重做开头与结尾，长版用完整案例和边界条件扩展。明确“刚好 120 秒”时帧数必须为 3,600，只有“约 8 分钟”时才按区间收片。

## 4　采样、词锚与中文嘴型

1. 先把每段语音录制或导入为 48 kHz PCM WAV，保留声道、原始文本、词典、采样数和段落局部起点。分片音频归零的时间戳必须加上该段在母带的起始采样。呼吸、停顿和片尾留白列入节目设计。
2. 每个词保留 section_id、word_id、[start_sample,end_sample)、置信度与人工修正标记。重复词用 ID 定位。cue 映射有序词 ID，查无此词、错版本或错段落时返回该 cue。
3. 共用边界取最近帧 `(sample + 800) // 1600`。例如 2,399 采样 → 第 1 帧，2,400 → 第 2 帧。内部镜头半开区间不得相互重叠或留缝。末尾不足一帧时按 `(samples + 1599) // 1600` 容纳最后一个有效采样，记录最多 1,599 个补齐采样。
4. 两个邻词可能量化到同一帧。保留两个原始采样锚，嘴型在该帧选择实际重音或合成曲线，不能生成负长度镜头。改语音后重新量化共享边界，从同一组绝对帧生成 SRT 毫秒数。
5. 将声韵、重音、停顿送至角色支持的嘴型。对 b/p/m 闭唇、圆唇、张口、静音建立有人工标注的试听集。口型过渡窗口按实际 Rig/音色在样片中校准。首次校准至少 100 个锚点，记录中位和 P95 绝对偏差、专名及混读子集。既有 80/150 ms 为待实片校准目标。

## 5　角色表演、图解和画质

角色包需包含原创正面及有限侧面参考、分层 PSD、Rig、表情、手势、嘴型、参数界限和使用记录。导演只填受支持的语义动作，例如“解释时指向图中蓝卡”。编译器先在 Scene Graph 找位置，再在批准的角度内映射动作。不可达的指向可以改选更近的机位或高亮该图形，返回镜头号供审核。角色身份、服装、发夹、眼色、光向和朝向都记录在基准图中。

场景分成主持人、知识图解、主题插画三类。首批配方只需覆盖“提问视线转向”“按口播逐步揭示流程”“对比两种结果”。每张配方写入作用层、允许参数、焦点、触发 cue、局部时间和结束状态。中文、代码、金额、箭头均由结构化元素绘制。检查移动路径中间帧的文字包围盒和字幕安全区，避免起终点均合法而过渡时遮挡。

背景所需有效像素由输出尺寸、裁剪和最大推近倍率决定。例如全幅横屏推近 1.5 倍且要求原像素覆盖时，底图至少 2880×1620。透明层在深底、浅底和棋盘底分别检查发丝与衣袖。统一直通/预乘 Alpha 的转换位置，保存放大截图和失败区域。调色、景深与动态模糊只应用到选定层。字幕和数据标签使用独立清晰层。旧文的一拍二/三换算到本项目 30 fps 为约 66.7 / 100 ms。

## 6　烘焙、相机和局部修订

Baker 从批准的初始姿态或上一镜指定末态开始，以固定步长 1/30 秒顺序计算表演、物理和次级动作，输出透明帧或可重放轨迹。输入记录 Rig、表演曲线、视素、种子、步长与烘焙器版本。合成器以 (镜头快照, 局部帧号) 查表。一个镜头的第 0 帧、末帧、反向取样和并行任务均使用同一份烘焙结果。

运镜按章共用舞台坐标，在讲解重点之间移动。静态阅读帧可显式登记目的和区间。层次可用前中后景的不同视差表现。转场明确持有两侧帧，通过切点只计一次节目时长。缓存键按依赖分层定义。

| 变更 | 重算 | 复用与重审 |
| --- | --- | --- |
| 字幕变色 | 字幕外观与受影响合成、最终媒体 QA | 研究、TTS、对齐、角色层复用。若变更改到 G3 样片，重审其新哈希 |
| 一镜表情 | 当前角色层、合成、显式继承新末态的后继 | 无其他依赖的图解和音频复用 |
| 第 4 章缩短 10 秒 | 该章音频、对齐、相关口型与绝对组装 | 原 8,100 帧边界移到 7,800。未重分配时母版为 470 秒。依赖局部时间的后章图层继续命中 |
| 数据值或事实 | 对应来源、论点、图表和相关口播 | 按受影响证据、文稿与媒体哈希重开 G1/G2/G3/G4/G5 中适用项 |

同机锁定引擎、字体、种子、颜色配置后比较同一帧 RGBA。不同硬件或有损编码保留解码环境和差异报告，先用样片校准视觉容差。过程并行只针对独立镜头。渲染机记录图形后端和实际样片，出现软件回退时展示能力与实测速度，部署参数按目标机器核验。

## 7　QA、预算与扩展

预检层先查合同、引用、动作能力、字体、安全区与整数时间。媒体层逐帧核对帧序，并检查未声明黑屏、单帧闪烁、长静止、缺声轨及端点。运动热图只作为提示，明确的图表阅读停留允许保留。有声审片层用 3×4 联系表定位镜头，用完整播放判断节奏与口播。可选独立视觉评审输出意见，G3/G4/G5 的决定由有权的人签发。

付费适配器先查缓存和限额，再预留预算、落提交意图、提交供应商。回执丢失时保留预留，以相同键查询。已确认结算产生唯一账本记录。可选英雄镜头接收已批准的 driving 片段、角色参考、帧预算和候选上限。候选审核后回嵌到同一镜头，并对入口、出口、角色身份与可见文字核对。无法取得许可或报价时，渠道保持关闭，默认主线可继续。

交付验收分三种事实。C00/C01 可验证项目合同与技术校准媒体。A01–A13 需要运行时、授权资产和可重放证据。A14/A15 需要真实短片及三期真实长片，A16 仅在启用可选渠道时执行。每项详细取证条件见[验收计划](验收计划.md)。
